# Security Scanner — Dashboard (Frontend)

واجهة React + TypeScript + Vite للتحكم بالفحوصات وعرض التقارير من الـ backend.

## الحالة: مكتمل ومُختبر end-to-end فعلياً

اختبرته بمتصفح Chromium حقيقي (Playwright) مع backend حقيقي شغّال، مرتين
(نسخة أولى وظيفية، ثم نسخة مُطوَّرة بصرياً):
- ✅ `npm run build` — صفر أخطاء TypeScript (بعد كل تعديل)
- ✅ فحص شبكة حقيقي (nmap) عبر الواجهة، من الضغط على الزر لحد ظهور النتيجة
- ✅ فحص ويب حقيقي (على سيرفر ضعيف تجريبي، XSS + SQLi) عبر الواجهة
- ✅ توليد التقارير الثلاثة (technical / managerial / non_technical) —
  تأكدت بصرياً (سكرين شوت فعلي) إن كل واحد يعرض محتوى مختلف فعلاً بنفس
  البيانات
- ✅ عرض المقارنة (AI + Rule-Based جنب بعض) — بما فيه حالة فشل AI (بدون
  API key) بدون ما يكسر الصفحة
- ✅ **زر تبديل اللغة (عربي/إنجليزي)** — يقلب اتجاه الصفحة كاملاً (RTL↔LTR)،
  كل نصوص الواجهة، **وأيضاً يعيد توليد آخر تقرير تلقائياً باللغة الجديدة**
  (بما فيه رد Gemini نفسه لمحرّك AI). اختبرته بعيني (سكرين شوت قبل/بعد):
  نفس التصنيف بالضبط (نفس أعداد Critical/High/Medium/Low/Info)، فقط
  النصوص واتجاه الصفحة اختلفوا

## اللغة (i18n)

- `src/i18n/strings.ts` — قاموس كل نصوص الواجهة الثابتة (أزرار، تسميات،
  رسائل حالة) بالعربي والإنجليزي
- `src/i18n/LanguageContext.tsx` — يدير حالة اللغة الحالية + `dir` (RTL/LTR)
  على مستوى `<html>` كامل، متاح لكل مكوّن عبر `useLanguage()`
- **محتوى التقارير نفسه** (findings، remediation، executive summary، ورد
  AI) **لا يُترجم بالواجهة** — يُطلب جاهزاً من الـ backend عبر حقل
  `language` بكل طلب تحليل (الـ backend فيه كل النصوص العربية ونظائرها
  الإنجليزية بملف `rules.py`، ورد Gemini نفسه يُطلب بلغة محدّدة عبر الـ
  system prompt)
- عند الضغط على زر تبديل اللغة، لو في تقرير معروض مسبقاً، `App.tsx` يعيد
  استدعاء نفس نوع التحليل (نفس المحرّك ونفس الجمهور) تلقائياً باللغة
  الجديدة — بدون ما تحتاج تعيد الضغط على "ولّد التقرير" يدوياً

## التصميم

هوية بصرية مقصودة: "غرفة عمليات أمنية حديثة" — خلفية غرافيت داكنة بتدرّج
خفيف، بطاقات مرفوعة بظلال ناعمة، وسلّم ألوان الخطورة (Critical→Info) هو
العنصر البصري المميّز الأساسي — يظهر كشبكة بطاقات إحصائية (أرقام حقيقية
من النتائج، مش placeholder) فوق شريط نسبي متناسب، ويتكرر بنفس اللغة
اللونية على كل بطاقة finding — لأنه فعلاً جوهر البيانات، مو زخرفة مضافة.

- **خطوط**: Space Grotesk للعناوين (طابع تقني حديث مميّز) + Inter للنصوص
  + IBM Plex Mono للبيانات/الكود + IBM Plex Sans Arabic للعربي
- **أيقونات**: lucide-react — أيقونة لكل قسم ولكل مستوى خطورة، بدل النص
  المجرّد
- **أزرق تشغيلي متدرّج** (gradient) للأزرار الأساسية، منفصل تماماً عن سلّم
  الخطورة عشان ما يتصادم بصرياً مع أي severity
- حركة دخول خفيفة (fade + slide) على البطاقات والتقارير، مع احترام
  `prefers-reduced-motion`

## التشغيل المحلي

### المتطلبات
- Node.js 18+ (مُختبر على v22)
- الـ backend شغّال على `http://127.0.0.1:8000` (راجع `../backend/README.md`)

### خطوات التشغيل

```bash
cd frontend
npm install

cp .env.example .env
# عدّل VITE_API_BASE_URL لو الـ backend على عنوان مختلف

npm run dev
```

افتح `http://localhost:5173`.

### بناء نسخة إنتاج (production build)

```bash
npm run build
npm run preview   # لمعاينة النسخة المبنية محلياً
```

## نقطة مهمة قبل الاستخدام: CORS بالـ backend

لازم يكون `CORS_ALLOWED_ORIGINS` بملف `.env` تبع الـ **backend** يحوي
عنوان الداشبورد (افتراضياً `http://localhost:5173` موجود مسبقاً بالقيمة
الافتراضية). لو شغّلت الداشبورد على عنوان/منفذ مختلف، أضفه هناك.

```
    styles/

    components/
      TopBar.tsx              # logo icon + wordmark + حالة اتصال حية بالـ backend
      NetworkScanControl.tsx  # بطاقة تشغيل فحص شبكة + متابعة حالته
      WebScanControl.tsx      # بطاقة تشغيل فحص ويب + متابعة حالته
      AnalysisControl.tsx     # اختيار المحرّك (أيقونات) + الجمهور
      SeverityStats.tsx       # شبكة بطاقات إحصائية + شريط نسبي (العنصر المميّز)
      FindingCard.tsx         # بطاقة finding واحدة، أيقونة severity، قابلة للطي
      ReportView.tsx          # StructuredReportView (AI/technical) + MarkdownReportView (managerial/non_technical كبطاقة "مستند")
      CompareView.tsx         # عرض AI و Rule-Based جنب بعض بأيقونات
    i18n/
      strings.ts               # قاموس نصوص الواجهة الثابتة (ar/en)
      LanguageContext.tsx      # حالة اللغة الحالية + dir (RTL/LTR)، متاح عبر useLanguage()
    App.tsx                 # الحاوية الرئيسية — تدير الحالة وتربط كل شي، وتعيد توليد التقرير عند تبديل اللغة
```

## قيود معروفة (المرحلة الحالية)

- **رسائل خطأ الـ backend التشغيلية تبقى عربية دائماً**: نصوص زي "لم يتم
  إيجاد nmap binary" أو أخطاء الـ scope guard مكتوبة بالكود مباشرة
  بالعربي فقط (مو جزء من نظام الترجمة). لو حبيت هذا يترجم لاحقاً، يحتاج
  تمرير `language` لملفات `core/config.py` و`modules/*/scanner.py` أيضاً
  — لسا ما عملناه، لأنه نطاق الميزة كان محتوى التقرير تحديداً.
- **الفحص synchronous من جهة الواجهة**: زر "شغّل الفحص" يبقى بحالة تحميل
  لحد ما الفحص يخلص فعلياً بالـ backend. لفحص `full` (65535 منفذ) هذا
  ممكن ياخد دقائق — الواجهة بتوضّح هذا بنص تحذيري، لكن ما في progress bar
  حقيقي (يحتاج معمارية background task + polling/WebSocket بالـ backend،
  مو مبني حالياً).
- **AI + audience غير technical غير مدعوم حالياً**: الـ backend ما عنده
  حالياً endpoint يولّد تقرير AI بصياغة managerial/non_technical (بس
  rule-based يدعم الثلاثة). لو حبيت هذا لاحقاً، يحتاج تعديل بسيط بـ
  `AIAnalyzer` يشبه اللي عملناه بـ `ReportFormatter`.
- **لا يوجد تخزين تاريخي**: كل نتيجة فحص/تحليل تعيش بالـ state تبع الصفحة
  فقط — تحديث الصفحة يفقد كل شي. يحتاج قاعدة بيانات (مذكورة بالمقترح
  الأصلي، لسا ما بنيت).
